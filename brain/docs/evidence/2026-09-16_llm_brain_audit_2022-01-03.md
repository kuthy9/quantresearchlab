## 1. Three defects the 2022-01-04 journal already contained

Read back after the fact, the 2022-01-04 run (45 accepted replies, one
episode that never slept) showed that the SLEEP ← ACTIVE half of the cycle
was unreachable on the real tape for three independent reasons. Each was
reproduced, fixed under a failing test, and re-measured.

| defect | evidence | fix |
| --- | --- | --- |
| A `NEUTRAL` verdict filed the item in `unresolved`, and any `unresolved` item refused sleep. The model uses `NEUTRAL` for "does not bear on the thesis". | 74 of 185 verdicts were `NEUTRAL`; `unresolved` reached 112 | `reducer.sleep_blockers` counts only *pending* items (`verdict` null). `NEUTRAL` stays recorded and resolvable. |
| Evidence an incident bar left unjudged could only leave `unresolved` through a `RESOLVE` carried by a *new* item — one per new item, never used by the model (0 `RESOLVE` in 45 replies). | 38 items parked by 7 incident bars, none ever cleared | `MainBrain.evidence_for` re-offers pending items in `new_evidence` (marked `pending_since`) on every call; the reducer files a re-offered item by the verdict it finally gets instead of rejecting it as a duplicate. |
| "No open interaction path" read the Eye's `ACTIVE` paths, which the Eye keeps alive as long as their context lives. Every row also showed `object_id: null`: a path's `context_id` is the tracker's own key, not an Eye object. | every one of the 181 bars of 2022-01-03 carried ≥ 1 ACTIVE path (595 rows, 1384 on 01-04), all unaliased; only 31 bars had a path that stepped that bar | `eye_view.interaction_rows` aliases each path to its source object (the zone for `zone_return`; the manipulation's source inventory item for `pool_reversal`), publishes `last_step_at` and `stepped_since_last_call`, and the runtime hands the last LLM call's `known_at` to `build_eye_context`. A path is *open* only if it stepped since that call (on the wake bar: this bar). |

A fourth defect surfaced on the first attempt at this window: DeepSeek closed
a connection without a response (`http.client.RemoteDisconnected`), which
`urlopen` raises bare, not inside `URLError`; the client did not map it and
the run crashed at 09:32 NY after 15 calls. Bare `http.client.HTTPException`
/ `OSError` failures now map to `LLMServerError` and retry.

## 4. Open after this run

- **The model does not ask to sleep.** The mechanism is proved on the real
  Eye by the echo run and on the synthetic Eye by `test_runtime.py`; the
  LLM itself kept 2–4 `watch_next` objects on every reply and never set
  `continue_active` false, even with the new prompt guidance. The next
  lever is either a stronger prompt rule or a controller-side timeout
  (e.g. N calls without an opportunity or a changed understanding).
- **Cost and latency.** 56 s median per call and ~1.0 M completion tokens
  for three hours of tape; a reply can lag the bar by two minutes. A lower
  reasoning budget or a smaller input (`prior_evidence_limit`, the 1m tape
  block, the full `price_relations` list) is the obvious knob.
- **`pool_reversal` paths are mostly unaliased** (40 of 270 rows aliased):
  their source inventory item is often not among the liquidity
  *candidates* the registry aliases. Aliasing inventory items would close
  that.
- The 01-04 journal (`6d82c83992806b44`) predates the `new_evidence` /
  `interaction` input shape and no longer replays sha-equal; its receipt
  stands as a historical record of that code.
